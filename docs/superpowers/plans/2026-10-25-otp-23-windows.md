# OTP-23 Windows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a disposable Chrome-to-WinRT synthetic BLE feasibility harness and collect physical Windows evidence.

**Architecture:** Keep the harness isolated under `native-bridge/feasibility/`. Separate bounded framing/protocol and fragmentation from Windows BLE ownership. A development extension launches one host and records synthetic results.

**Tech Stack:** Rust, WinRT windows crate, Chrome MV3 JavaScript, PowerShell, existing Android GATT service.

**Spec:** `docs/superpowers/specs/2026-10-25-otp-23-windows-design.md`; authoritative OTP-23 RFC section.

## Global Constraints

- Synthetic data only; no cryptography, trust, installers or production bridge reuse.
- Exact-origin development manifest; Chrome-owned stdin/stdout only.
- macOS acceptance and overall feasibility decision remain pending.
- Build Android here; Windows compilation and hardware validation require PC.

## Review Focus

- Oversized/truncated frames terminate without allocation abuse or unframed stdout.
- Delayed callbacks and EOF release scans and links.
- Concurrent requests retain request IDs and independent phone handles.
- Subscription/MTU order interoperates with OTP-06.
- Background delivery is measured without throttling exemptions.

### Task 1: Disposable host and connector

**Files:** Create `native-bridge/feasibility/` Rust crate, extension and registration script.

**Interfaces:** JSON requests `hello`, `start_scan`, `stop_scan`, `connect`, `disconnect`, `send`, `shutdown`; correlated success/error events and unsolicited device/message events. Records match OTP-06 framing and limits.

- [ ] Add failing Rust tests for bounded frames, malformed requests and record fragmentation/reassembly boundaries.
- [ ] Run tests and confirm failures before implementation.
- [ ] Implement portable protocol helpers and Windows WinRT backend, single stdout owner, bounded queues and cleanup.
- [ ] Add exact-origin MV3 connector and per-user registration tooling.
