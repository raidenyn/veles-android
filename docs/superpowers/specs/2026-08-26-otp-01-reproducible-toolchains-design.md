# OTP-01: Add reproducible Chrome and cryptographic toolchains to Gradle — design

Status: Draft
Issue: raidenyn/veles-android#80
RFC: docs/rfcs/2026-08-21-otp-external-devices.md, section `### OTP-01`
Gate: Gate A (protocol and toolchain foundation)

## Purpose

Give the repository a deterministic way to install, lint, type-check, test,
build, and package the TypeScript MV3 extension, the Rust core placeholder
crate used to validate JNI and WASM plumbing (the real SPAKE2 core lands in
OTP-03), and the unsigned Tauri native-bridge release
inputs for Windows and macOS — all exposed as Gradle entry points, all pinned,
all byte-reproducible in clean environments.

OTP-01 delivers the toolchain foundation that Gate A and every later OTP task
depend on. It contains **no** Bluetooth transport, **no** cryptographic
protocol behavior, **no** UI, and **no** real OTP integration (RFC
"Exclusions" — preserved verbatim here as the acceptance boundary).

## Classified path

Architectural → decomposed into four sub-projects per user decision. Each
sub-project gets its own spec→plan→implement cycle. This document is the
single OTP-01 decomposition spec; sub-project 1a is designed in full here
because it is the first to be built. Sub-projects 1b/1c/1d are designed at
boundary level; their implementation specs are written when 1a is in review.

## Sub-projects and sequencing

| # | Sub-project | Deliverable | Feed into |
|---|---|---|---|
| 1a | TS/MV3 extension toolchain | `web-extension/` npm/Vite project + Gradle tasks + deterministic zip | OTP-02, 05, 07, 17, 18 |
| 1b | Rust core + JNI/WASM | `rust/` workspace, jniLibs for Android ABIs, `web-extension/rust-wasm/pkg` | OTP-02→03, 06 |
| 1c | Tauri native-host packaging | unsigned Windows/macOS bridge binaries, host manifests, per-user installer inputs | OTP-23, 24, 25 |
| 1d | Verification & supply chain | `verify/` extension + SBOM + license + byte-compare harness | Gate A, Gate D |

Canonical order: **1a → 1b → 1c → 1d**. Rationale: each sub-project must
leave artifacts in place for the next to consume; 1d verifies all three and
therefore cannot close until build outputs exist.

## Global decisions (apply to 1a / 1b / 1c / 1d)

1. **Toolchain provisioning is PATH-based, minimum-version declared.**
   node/npm/rustup/cargo are not downloaded by Gradle. `package.json
   engines.node`, `rust-toolchain.toml` channel, and Cargo minimum-version
   are the declared pins. `verify/` Docker images (1d) bake exact versions
   for byte-compare environments; developer machines need only satisfy the
   declared minimum.
2. **Lockfiles are the reproducibility contract.** `package-lock.json` and
   `Cargo.lock` are committed and builds run `--locked` / `npm ci`. Drift
   fails the build; never auto-fixed in CI.
3. **Artifacts land under `build/`, not inside source trees.** Gradle's
   `clean` wipes them. The only exception is `web-extension/rust-wasm/pkg`
   produced by 1b and consumed by `web-extension/`, because Vite expects
   import paths inside the project tree. That directory is gitignored and
   regenerated by `rustWasm` before `extensionBuild` runs.
4. **New Gradle tasks join existing `check`.** Format/lint/typecheck/test
   tasks from every sub-project are wired as dependencies of the root
   `check` so `.github/workflows/ci.yml` picks them up without changes.
5. **APK build is unaffected.** No new Gradle subprojects under
   `settings.gradle.kts` (`:app` remains the only included project). All
   new tasks live in the root `build.gradle.kts`, grouped under
   `extension`, `rust`, `native-bridge`, `verification` task groups. Clean
   clones without node/rust can still run `./gradlew :app:assembleDebug`.

## Sub-project 1a: TypeScript/MV3 extension toolchain (full design)

### Layout

```
web-extension/
  package.json            # name "@veles/web-extension", engines.node >= declared min
  package-lock.json       # committed
  tsconfig.json           # strict
  vite.config.ts          # two entries: background (service worker), content
  src/
    manifest.ts           # generates MV3 manifest.json for dist/
    background.ts         # service worker entry stub
    content.ts            # content-src entry stub
  test/
    smoke.test.ts         # vitest smoke tests (manifest shape, entry exports)
  .eslintrc.cjs           # eslint config
  .prettierrc             # prettier config
  public/                 # icons and statics copied by vite
```

### Gradle tasks (group `extension`, defined in root `build.gradle.kts`)

| Task | Command | Depends on | Output |
|---|---|---|---|
| `extensionInstall` | `npm ci --prefix web-extension` (skipped with a descriptive message when `web-extension/package-lock.json` is absent so Android-only workflows still run) | — | `web-extension/node_modules` |
| `extensionFormat` | `prettier --check web-extension` | `extensionInstall` | — |
| `extensionLint` | `eslint web-extension` | `extensionInstall` | — |
| `extensionTypecheck` | `tsc --noEmit -p web-extension/tsconfig.json` | `extensionInstall` | — |
| `extensionTest` | `vitest run` in `web-extension` | `extensionInstall` | — |
| `extensionBuild` | `vite build` in `web-extension` | `extensionInstall`, `extensionTypecheck` | `web-extension/dist/` |
| `extensionPackage` | deterministic zip of `dist` + manifest/CSP guard | `extensionBuild` | `build/web-extension/veles-extension-<version>.zip` + `.sha256` |

Wiring: root `check` depends on `extensionFormat`, `extensionLint`,
`extensionTypecheck`, `extensionTest`. `extensionBuild` and
`extensionPackage` are invoked explicitly (release-style), not from `check`.

### Deterministic packaging recipe (used by `extensionPackage`)

- ZIP entries sorted lexicographically by name.
- All entry mtimes set to `1980-01-01T00:00:00Z` (DOS epoch) to avoid host
  clock leakage.
- No extra fields, no comments, no directory entries beyond what zip
  requires.
- Deflate level fixed; implementation is a Gradle `Zip` task with
  `preserveFileTimestamps = false`, `reproducibleFileOrder = true`,
  `entryCompression = DEFLATE`.
- After zip, a Gradle task reads `dist/manifest.json` and fails the build
  unless:
  - `manifest_version == 3`,
  - `permissions` is `[]` or absent,
  - no `host_permissions` or `content_security_policy` override weaker
    than the declared baseline in `src/manifest.ts`.

### Error handling

| Failure | Behavior |
|---|---|
| `node`/`npm` missing from PATH | Gradle task fails fast with `Could not find 'node' on PATH; install Node.js >= <engines.node>` (mirrors `verify/verify.sh` pin-error style). |
| `package-lock.json` drift (`npm ci` non-zero) | Hard fail. No `npm install` fallback. |
| Manifest/CSP guard trip | `extensionPackage` fails naming the violated guard. |
| `web-extension/package-lock.json` absent | All `extension*` tasks skipped with descriptive messages (see task table) — lets an Android-only developer run `./gradlew build` without node. |

### Versioning

The extension artifact name embeds `web-extension/package.json` `version`
(manually bumped per extension release). This is deliberately independent
of the Android app's git-tag-derived versionName — the extension and the
APK ship on separate tracks.

### Testing (sub-project-level, before wiring into CI)

- `vitest run` covers: manifest generator emits expected MV3 shape, zip
  entry list matches a checked-in expected-file snapshot, both entry
  points compile and export.
- Byte-determinism is asserted in 1d via double-build hash-compare, not in
  1a. 1a's job is to make the zip recipe deterministic so 1d can compare
  hashes without surprises.

## Sub-project 1b: Rust core + JNI/WASM (boundary)

- **Layout:** `rust/` workspace with one crate `veles-crypto` exposing both
  `extern "C"` JNI shims and `wasm-bindgen` exports. Sibling crates for
  JNI/WASM bindings split only if feature gating becomes unmanageable.
- **Toolchain:** `rust/rust-toolchain.toml` pins the channel (e.g.
  `channel = "1.xx.x"`, `targets = [...]`, `components = ["clippy",
  "rustfmt"]`). Gradle does not fetch rustup; builds assume `cargo` on
  PATH satisfying the `rust-toolchain.toml`.
- **Placeholder content (per user):** `veles-crypto` exposes exactly one
  operation through both bindings, chosen at implementation time purely to
  exercise the plumbing — any deterministic function of input bytes to
  output bytes (a hash, a fixed transform, etc.) is acceptable. The choice
  is non-binding and carries no cryptographic meaning. No SPAKE2, no key
  material, no protocol-level state. Inputs/outputs use a simple
  byte-buffer contract that does not presuppose OTP-02's protocol
  decisions and will be replaced wholesale when OTP-03 lands.
- **Gradle tasks (group `rust`):**
  - `rustInstall` — no-op placeholder that validates `cargo` presence and
    `rust-toolchain.toml` parse, matching the `extensionInstall` style.
  - `rustJni` — `cargo build --locked --release --target
    aarch64-linux-android` (plus `armv7-linux-androideabi`,
    `x86_64-linux-android`), copies `.so` files into
    `app/src/main/jniLibs/<abi>/`. `assembleDebug`/`assembleRelease`
    depend on it, so a plain APK build pulls the .so automatically.
  - `rustWasm` — `wasm-pack build --target web --out-dir
    ../../web-extension/rust-wasm/pkg` (or `wasm-bindgen-cli` equivalent).
    Output committed-ignored; regenerated before `extensionBuild`.
  - `rustFormat` (`cargo fmt --all -- --check`), `rustLint` (`cargo
    clippy --all-targets --locked -- -D warnings`), `rustTest` (`cargo
    test --locked`). Wired into root `check`.
- **NDK:** uses the NDK installed by AGP under `local.properties`/SDK
  manager, no separate pin file inside `rust/`. NDK version recorded in
  `libs.versions.toml` (`ndk = "x.y.z"`) and propagated to
  `app/build.gradle.kts` `android.ndkVersion`.

## Sub-project 1c: Tauri native-host packaging (boundary)

- **Layout:** `native-bridge/` at repo root, a Tauri 2.x headless app
  (`src-tauri/`, `tauri.conf.json`, minimal `index.html` as a placeholder
  entry that is never shown).
- **User-confirmed posture:** Tauri configured with **`windows = []`** and
  all default features disabled (per decision "Tauri headless lifecycle"
  assessed at Gate D). No tray, no menu, no autostart, no login item. The
  process exits on stdin EOF, matching Native Messaging semantics.
- **Toolchain:** `tauri.conf.json`'s own npm devDeps follow the same
  `engines.node` minimum + committed `package-lock.json` pattern as 1a.
- **Gradle tasks (group `native-bridge`):**
  - `bridgeInstall` (`npm ci` inside `native-bridge/`), `bridgeFormat`,
    `bridgeLint`, `bridgeTypecheck` if any TS config, `bridgeTest`
    (`cargo test --locked` inside `src-tauri/`).
  - `bridgeBuild` — `cargo tauri build --locked --no-bundle` producing
    the unsigned binary for the host OS.
  - `bridgePackage` — platform-specific:
    - **Windows:** zip payload containing the `.exe`, native-messaging
      host manifest JSON, and installer inputs (WiX / NSIS files Tauri
      emits) into `build/native-bridge/windows/`.
    - **macOS:** tar payload containing the `.app` bundle (unsigned),
      host manifest, installer inputs into `build/native-bridge/macos/`.
  - `bridgeManifests` — emits the Chrome native-messaging host manifest
    for each OS with exact host-origin fields pinned to the extension ID
    placeholder used in 1a.
- **Explicitly excluded:** no BLE calls, no crypto, no signed artifacts.
  Tauri signing env vars (`TAURI_SIGNING_PRIVATE_KEY` etc.) are documented
  as absent in CI. `tauri.conf.json` hard-codes unsigned output.

## Sub-project 1d: Verification & supply chain (boundary)

- **Docker environments:** `verify/Dockerfile.web` (node@pinned + `npm ci`
  + `vite build` + sha256 of zip) and `verify/Dockerfile.rust`
  (rust@pinned + `cargo build --locked` for JNI and WASM targets + sha256
  of outputs). Existing `verify/Dockerfile` for Android unchanged.
- **Compare script:** `verify/verify-all.sh` builds all three reference
  images, extracts hashes, compares against a checked-in
  `SHA256SUMS.toolchains`. Exit codes mirror `verify.sh` (0 match, 1
  mismatch, 2 usage/pin error).
- **SBOM:** `cyclonedx-npm` for `web-extension/`, `cargo cyclonedx` for
  `rust/` and `native-bridge/src-tauri/`. Output JSON files into
  `build/sbom/{web-extension,rust,native-bridge}.cdx.json`.
- **License:** `license-checker-rseidelsohn` for npm, `cargo deny
  licenses` for Rust. Report under `build/licenses/`; a `deny.toml` in
  `rust/` and an allowlist in license config fail CI on copyleft
  licenses (GPL/AGPL/SSPL/CC0 excluded by default).
- **Checksums:** `SHA256SUMS` files per artifact tree produced by the
  `*Package` tasks, uploaded as CI artifacts.

## Acceptance criteria (traceable to RFC OTP-01)

1. Clean `./gradlew clean check extensionPackage` on a fresh clone
   reproduces `veles-extension-<version>.zip` byte-identical across two
   runs on the same machine with identical `package-lock.json`.
2. `verify/verify-all.sh` (added in 1d) reproduces the same hashes inside
   pinned Docker images; matches `SHA256SUMS.toolchains`.
3. `./gradlew :app:assembleRelease` embeds `jniLibs/<abi>/libveles_crypto.so`
   for the three declared ABIs and no others.
4. `web-extension/rust-wasm/pkg/` regenerates deterministically and
   imports cleanly into the extension skeleton.
5. Windows and macOS builds on CI runners produce unsigned bridge
   binaries + installer inputs whose hashes are recorded in
   `SHA256SUMS.native-bridge`.
6. Root `check` fails on any new copyleft dependency.
7. Gradle entry points are documented in README / CLAUDE.md.

## Error-handling rules (global)

- No Gradle task performs a network fetch other than `npm ci` /
  `cargo fetch` against a committed lockfile. Everything else is pinned.
- Clean failure fast: missing tool → exit code 2-equivalent message
  naming the missing tool and the pinning file that should have provided
  it.
- No auto-fix: lockfile drift, format drift, lint findings all abort
  rather than rewrite.

## Out of scope (explicitly, per RFC and this decomposition)

- SPAKE2 protocol implementation (OTP-03), protocol freeze (OTP-02),
  Android BLE service (OTP-06), Chrome native-messaging connector
  (OTP-07), installers with signing (OTP-25), any UI, any OTP integration,
  any runtime download.

## Risks and open questions

- Cargo and npm lockfile byte-determinism across hosts: different OS
  line-endings or registry mirrors can produce different lockfiles from
  the same input. Mitigation: lockfiles are committed and compared
  byte-for-byte in `verify/verify-all.sh`.
- Tauri headless-mode stability (`windows = []`) is a Gate D review item;
  1c's skeleton proves the build produces the right artifact shape, not
  that the runtime behaves.
- Vite plugin pinning: some Vite plugins float on minor versions
  unless explicitly pinned; the spec mandates exact-version pinning in
  `package.json` (no caret).
- WASM loading inside an MV3 CSP is a known sharp edge
  (`'wasm-unsafe-eval'` required in `content_security_policy`). 1a's
  manifest guard permits exactly that one relaxation; no others.
