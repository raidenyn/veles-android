## 2. The completion hold

- [ ] 2.1 Timers and constants: add `setTimeout`/`clearTimeout` deps to `PairingLinkDeps` with global defaults, rename `clearTimer()` to `clearTimers()` so it clears the tick and the hold, and add `ACTIVATION_HOLD_MS = 5000`; add `setInterval`/`clearInterval` to `ConnectorAppDeps` and forward the complete timer set when `connector.ts` starts the link, still passing no `tickIntervalMs` (D3, D8).
- [ ] 2.2 Link state: add `draining` and `peerClosed` (plus the existing one-shot `ended`), subscribe `onConnectionClosed` in `start()` right after `connect` resolves and before the first `send` (`link.ts:171-208`), and unsubscribe it on every startup failure exit. The notification only sets the latch — it never stops the link or calls `onDisconnect()` before activation (D3).
- [ ] 2.3 Arm the hold after the ack's frames are sent, when `activationCompleted()` holds (`machine.closed && machine.state === 'active'`): unsubscribe `onRecord`, drop any record already queued through `draining`, finish at once when the latch is set, otherwise wait for the peer close or the bound; the frame-queue item returns without awaiting the bound so `terminate()` is never delayed (D3).
- [ ] 2.4 Finish the hold in one place: a peer close ends through `stop()` with its disconnect request skipped (no `onDisconnect()`, it calls `notifyEnded()`, and it schedules no recovery); the bound expiring issues exactly one disconnect request and leaves the machine `active`; a failed final send keeps its request so no handle leaks. Every finish sets `stopped`, clears both timers and unsubscribes the close listener before any disconnect, so a later `terminate()` or `closeAll()` cannot re-select the ended link or issue a second request (D4, D5).
- [ ] 2.5 Terminal-active rule: guard `terminate()`/`abandon()`, and the `receive` catch that calls `machine.onDisconnect()` (`link.ts:311`), so a completed activation skips that call; leave `cancel()`/`dispose()` as they are, with the machine ending `idle` without a failure and the `active_activation_pending` mirror untouched (D4).
- [ ] 2.6 Reachability: sample `machine.boundPeerId()` after every `onFrame` return and after `commit()`, keep the last non-null value, and answer the link's `boundPeerId()` with `machine.boundPeerId() ?? remembered` from `activationCompleted()` until the link has finished (`stopped`), so a revocation that lands while the ack send is still pending still selects the link, and a later revocation cannot re-select an ended one. Test both: a revocation during the ack send, and `SessionManager.closePeer` closing a held link (D4).
