## Configuration-cache opt-outs

Task 4.4. The release/PR packaging pipeline is not rewritten for the configuration cache; every task
in it carries (design D2, D6):

```kotlin
notCompatibleWithConfigurationCache(
    "release/PR packaging pipeline; always run with --no-configuration-cache, see docs/reproducible-builds.md",
)
outputs.doNotCacheIf("release packaging") { true }
```

The reason string is the one `docs/reproducible-builds.md` must state (Task 9). Every task below runs
only in a guarded invocation (`--no-build-cache --no-configuration-cache`; Task 6 adds the flags).

### Observed behaviour (Gradle 9.5.0, Linux, 2026-11-20)

`notCompatibleWithConfigurationCache` does not hide the pipeline from the configuration-cache report:
a run that includes an opted-out task still serialises the task, reports
`cannot serialize Gradle script object references as these are not supported with the configuration cache`
for each opted-out task, and ends with `Configuration cache entry discarded with N problems.` It does
make the build succeed despite `org.gradle.configuration-cache.problems=fail` (the tasks are marked
incompatible, so the entry is discarded rather than failing the build), and it records the reason in
the HTML report. For example:

```
$ ./gradlew --console=plain bridgeInstallerPackageFixture
Calculating task graph as no cached configuration is available for tasks: bridgeInstallerPackageFixture
...
FAILURE: Build failed with an exception.
* What went wrong:
Execution failed for task ':bridgeInstallerToolObservation' (registered in build file 'build.gradle.kts').
> OTP-25 installer inputs are built on a Windows or macOS runner; Linux is not a producer target.
...
Configuration cache entry discarded with 37 problems.
```

(That run fails on the producer's own Linux refusal, not on the configuration cache.) This is why the
guarded CI invocations pass `--no-configuration-cache`; with that flag the pipeline runs without a
configuration-cache report at all. The same mechanism was reproduced in a two-task scratch build: an
opted-out task that captures a script-level value reports one problem, discards the entry and leaves
the build successful under `problems=fail`.
